**→ P1 corrected: a key could remain pressed after a live remap.** Press Q at row 0, column 0, remap that crossing to A, then release it. The original implementation left Q in the HID report. Pinned QMK caches the source layer, then reads the current mapping when it processes release. The new mapping therefore caused release of A instead of Q.

Evidence is in `.audit/profiles-held-red.log:142`, which records `editing a held key must not leave its original HID usage pressed` at test source line 161. The execution owner reported exit 133. The source chain is `external/qmk_firmware/quantum/action_layer.c:299`, `external/qmk_firmware/quantum/quantum.c:229`, and `external/qmk_firmware/quantum/dynamic_keymap.c:122`. All dependency paths in this paragraph are relative to `keyboards/ck5200`.

The correction in [ck5200_keymap.c](../../firmware/platform/ch32x035/ck5200_keymap.c), lines 26, 113, and 119, checks every debounced matrix row before `CMD_SET_KEY` or `CMD_RESET`. If any key is down, the handler returns status `0x02` before changing RAM. The guard adds no state. The normal foreground loop completes matrix event processing before it handles another command, so the guard does not run between the scan and its release events.

The regression in [QMKProfileTests.swift](../../../../ios/ClicksInspector/Tests/QMKProfileTests.swift) verifies rejection, unchanged RAM after reconnect, and an empty HID report after release. It also covers restore rejection with held Shift, LT, and consumer keys. The inspected `.audit/ios-guard-tests.log` records both held-key PASS lines. A completed OSL tap can retain the existing one-shot layer while no key is down. The correction does not change that QMK behavior.

**→ Controller and storage checks.** The reviewed controller requires the exact CK-5200 model, hardware revision `1.2.0`, and `QM 00 01` identity before custom keymap commands. Writes also require a verified read and the session RAM-write switch. Reconnect clears that permission. Old session callbacks cannot affect the new session because callbacks and exchanges check the session generation.

The controller stops on lost, malformed, or mismatched replies and requires reconnect. It does not retry an ambiguous write. Profile selection and saving use atomic JSON writes. Invalid schema, invalid dimensions, duplicate IDs, invalid desired IDs, and corrupt JSON fail validation. A failed profile load preserves the file and blocks replacement through the controller.

Every iOS build keeps `stockUpdatesEnabled` false. The RAM permission does not authorize `0xA0` through `0xA3`. Arbitrary QMK reset keycodes use the existing platform reset hooks. Those hooks call `NVIC_SystemReset`; they do not provide a firmware flashing path. No flashing permission was inferred from the RAM editor.
